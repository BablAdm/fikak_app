# Fikak App - Complete Setup & Testing Guide

## Overview

This guide will help you set up and test the complete Fikak App ecosystem with all integrations:

- **Frontend**: fikak-ui (Next.js 14 with React 18)
- **Backend**: Frappe Framework (Python-based ERP)
- **Database**: MariaDB 10.6
- **Cache/Queue**: Redis
- **Proxy**: Nginx

### Architecture

```
                    Internet/User
                          │
                    ┌─────▼─────┐
                    │   Nginx   │  Port 80
                    │   Proxy   │
                    └─────┬─────┘
                          │
        ┌─────────────────┼─────────────────┐
        │                                   │
   ┌────▼────┐                         ┌───▼──────┐
   │ Fikak UI│  Port 3000               │  Frappe  │  Port 8000
   │(Next.js)│                         │ Backend  │
   └─────────┘                         └────┬─────┘
                                            │
                          ┌─────────────────┼────────────┐
                          │                 │            │
                     ┌────▼────┐       ┌───▼───┐   ┌───▼────┐
                     │ MariaDB │       │ Redis │   │Workers │
                     │  3306   │       │ 6379  │   │        │
                     └─────────┘       └───────┘   └────────┘
```

## Step-by-Step Setup

### Step 1: Unified Stack Architecture

The unified stack uses a simple architecture:
- **Frontend**: Nginx reverse proxy (forwards requests to Frappe backend)
- **Backend**: Frappe Framework with MariaDB, Redis, and workers
- **Multi-language**: Handled by Frappe (not a separate Next.js app)

No separate frontend repository or `.env.local` configuration is needed—the nginx-ui.conf is configured automatically.

### Step 2: Configure Docker Compose

The `docker-compose.unified.yml` file orchestrates all services. Review the configuration:

```bash
cd fikak_app  # your cloned repository root
cat docker-compose.unified.yml
```

**Environment variables** (optional, create `.env` file):
```env
# Database password
DB_PASSWORD=<generated by setup.sh - see your .env>

# Frappe site name
FRAPPE_SITE_NAME=localhost
```

> **Note for manual commands:** any `docker exec` command below that uses
> `$DB_PASSWORD` or `$ADMIN_PASSWORD` needs those variables in your shell first:
>
> ```bash
> export DB_PASSWORD=$(grep '^DB_PASSWORD=' .env | cut -d= -f2-)
> export ADMIN_PASSWORD=$(grep '^ADMIN_PASSWORD=' .env | cut -d= -f2-)
> ```

### Step 4: Start All Services

```bash
# From your cloned repository root
cd fikak_app

# Start all services
docker compose -f docker-compose.unified.yml up -d

# Check status
docker compose -f docker-compose.unified.yml ps

# Watch logs (optional)
docker compose -f docker-compose.unified.yml logs -f
```

**Expected services:**
- ✅ fikak_mariadb - Database (healthy)
- ✅ fikak_redis_cache - Cache layer (healthy)
- ✅ fikak_redis_queue - Queue system (healthy)
- ✅ fikak_configurator - Configuration setup (completed)
- ✅ fikak_backend - Frappe backend (healthy)
- ✅ fikak_queue_short - Short queue worker
- ✅ fikak_queue_long - Long queue worker
- ✅ fikak_scheduler - Scheduled jobs
- ✅ fikak_ui - Frontend (healthy)
- ✅ fikak_proxy - Nginx proxy (healthy)

### Step 5: Initialize Frappe Site

After all services are running, create a Frappe site:

```bash
# Create the default site
docker exec -it fikak_backend bash -c "bench new-site localhost \
  --mariadb-root-password \"$DB_PASSWORD\" \
  --admin-password \"$ADMIN_PASSWORD\" \
  --no-mariadb-socket"

# Set site as current
docker exec -it fikak_backend bash -c "bench use localhost"

# Enable developer mode (optional, for testing)
docker exec -it fikak_backend bash -c "bench set-config developer_mode 1"
```

**Login credentials:**
- **Username**: Administrator
- **Password**: the `ADMIN_PASSWORD` value in your `.env` (generated by setup.sh)

### Step 6: Install Fikak Custom App

The fikak_api is a private repository that contains the custom Frappe app for fikak functionality.

#### Option A: Using SSH (Recommended)

```bash
# 1. Copy your SSH private key to the backend container
docker cp ~/.ssh/id_rsa fikak_backend:/tmp/id_rsa
docker cp ~/.ssh/id_rsa.pub fikak_backend:/tmp/id_rsa.pub

# 2. Set up SSH in container
docker exec -it fikak_backend bash -c "
  mkdir -p ~/.ssh && \
  cp /tmp/id_rsa ~/.ssh/ && \
  cp /tmp/id_rsa.pub ~/.ssh/ && \
  chmod 600 ~/.ssh/id_rsa && \
  chmod 644 ~/.ssh/id_rsa.pub && \
  ssh-keyscan github.com >> ~/.ssh/known_hosts
"

# 3. Get the fikak_app from GitHub using SSH
docker exec -it fikak_backend bash -c "bench get-app fikak_app git@github.com:BablAdm/fikak_api.git"

# 4. IMPORTANT: remove the private key from the container immediately after cloning
docker exec -it fikak_backend bash -c "rm -f /tmp/id_rsa /tmp/id_rsa.pub ~/.ssh/id_rsa ~/.ssh/id_rsa.pub"
# Tip: prefer a short-lived, repo-scoped deploy key over your personal key,
# and verify GitHub's host key fingerprint (https://docs.github.com/en/authentication/keychain)

# 5. Install the app on the site
docker exec -it fikak_backend bash -c "bench --site localhost install-app fikak_app"

# 5. Migrate database
docker exec -it fikak_backend bash -c "bench --site localhost migrate"

# 6. Restart bench
docker exec -it fikak_backend bash -c "bench restart"
```

#### Option B: Clone Locally and Mount

If you have the repository cloned locally:

```bash
# 1. Clone fikak_api locally
cd workspace
git clone git@github.com:BablAdm/fikak_api.git

# 2. Copy to backend container
docker cp workspace/fikak_api fikak_backend:/home/frappe/frappe-bench/apps/fikak_app

# 3. Install the app
docker exec -it fikak_backend bash -c "
  cd apps/fikak_app && \
  pip install -e . && \
  cd ../.. && \
  bench --site localhost install-app fikak_app
"

# 4. Migrate and restart
docker exec -it fikak_backend bash -c "bench --site localhost migrate"
docker exec -it fikak_backend bash -c "bench restart"
```

#### Verify Installation

```bash
# List installed apps
docker exec -it fikak_backend bench --site localhost list-apps

# Expected output should include:
# - frappe
# - fikak_app
```

2. Navigate through the menu:
   - Dashboards
   - User Profile
   - Settings

### Test 3: API Integration

Test Frappe API endpoints directly:

```bash
# Login and get session
curl -X POST http://localhost:8000/api/method/login \
  -H "Content-Type: application/json" \
  -d '{
    "usr": "Administrator",

  }'

  -H "Cookie: <session-cookie-from-login>"
```

1. Change language in settings (English, Arabic, French)
2. Verify RTL support for Arabic
3. Check translations are working

### Test 5: Real-time Updates (WebSocket)

1. Open browser developer console
2. Navigate to Network tab → WS (WebSocket)
3. Verify Socket.IO connection at `/socket.io`
4. Trigger actions and watch real-time events

## Troubleshooting

### Issue: Frappe backend won't start

**Symptoms**: Backend container exits or shows errors

**Solutions**:
```bash
# Check logs
docker compose -f docker-compose.unified.yml logs fikak_backend

# Ensure MariaDB is healthy
docker compose -f docker-compose.unified.yml ps mariadb

# Restart backend
docker compose -f docker-compose.unified.yml restart fikak_backend

# Rebuild if needed
docker compose -f docker-compose.unified.yml up -d --build fikak_backend
```

### Issue: Site not created

**Symptoms**: "Site localhost does not exist"

**Solution**:
```bash
# Create site manually
docker exec -it fikak_backend bench new-site localhost \
  --mariadb-root-password "$DB_PASSWORD" \
  --admin-password "$ADMIN_PASSWORD" \
  --no-mariadb-socket

# Verify site exists
docker exec -it fikak_backend bench --site localhost list-apps
```

### Issue: Frontend can't connect to backend

**Symptoms**: API errors in browser console

**Solutions**:
1. Verify backend is running: `curl http://localhost:8000`
2. Check environment variable: `NEXT_PUBLIC_FRAPPE_BASE_URL`
3. Verify network connectivity:
   ```bash
   docker network inspect fikak_network
   ```
4. Check Nginx proxy logs:
   ```bash
   docker compose -f docker-compose.unified.yml logs nginx_proxy
   ```

### Issue: Port conflicts

**Symptoms**: "Port already in use" errors

**Solution**:
```bash
# Check which ports are in use
lsof -i :80
lsof -i :3000
lsof -i :8000
lsof -i :3306

# Stop conflicting services or modify docker compose ports
```

### Issue: Out of memory

**Symptoms**: Containers crashing, slow performance

**Solution**:
```bash
# Check Docker resource limits
docker stats

# Increase Docker memory in Docker Desktop/daemon settings
# Minimum: 8GB recommended

# Or scale down workers
docker compose -f docker-compose.unified.yml up -d --scale frappe_queue_long=0
```

### Issue: CORS errors

**Symptoms**: Browser blocks API requests

**Solution**:
```bash
# Check Frappe CORS settings
docker exec -it fikak_backend bench --site localhost set-config allow_cors "\"http://localhost:3000\""

# Restart backend
docker compose -f docker-compose.unified.yml restart fikak_backend
```

## Stopping & Cleaning Up

### Stop Services

```bash
# Stop all services
docker compose -f docker-compose.unified.yml down

# Stop and remove volumes (WARNING: deletes all data)
docker compose -f docker-compose.unified.yml down -v
```

### Clean Up

```bash
# Remove all fikak containers
docker compose -f docker-compose.unified.yml rm -f

# Remove volumes
docker volume prune

# Remove images (if rebuilding)
docker image prune -a
```

### Backup & Restore

```bash
# Backup Frappe site
docker exec -it fikak_backend bench --site localhost backup \
  --with-files

# Backups location (inside container)
# /home/frappe/frappe-bench/sites/localhost/private/backups/

# Copy backup to host
docker cp fikak_backend:/home/frappe/frappe-bench/sites/localhost/private/backups/ ./backups/

# Restore (on new installation): copy the backup into the container first,
# because bench restore reads paths inside the container.
# Backup files are timestamped (e.g. 20240101_120000-localhost-database.sql.gz);
# check ./backups/ and substitute the actual filename below.
docker cp ./backups/<timestamp>-localhost-database.sql.gz fikak_backend:/tmp/backup.sql.gz
docker exec -it fikak_backend bench --site localhost restore \
  /tmp/backup.sql.gz \
  --mariadb-root-password "$DB_PASSWORD"
```
